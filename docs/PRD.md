# 🔗 마이링크 (MyLink) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
### 1.1. 프로젝트명
**마이링크 (MyLink)**

### 1.2. 목적
사용자의 다양한 소셜 미디어, 포트폴리오, 블로그 등 흩어져 있는 온라인 접점을 **하나의 직관적인 URL(Single Point of Entry)**로 통합하여 제공합니다. 강력한 비주얼과 단순한 관리 기능을 통해 퍼스널 브랜딩의 효율을 극대화합니다.

### 1.3. 대상 사용자
*   **크리에이터 / 인플루언서:** 인스타그램, 유튜브, 틱톡 등 팔로워에게 모든 채널을 한 번에 안내하고 싶은 사용자.
*   **프리랜서 / 포트폴리오 관리자:** 서비스 소개, 예약, 작업 결과물 링크를 전문적으로 공유하고 싶은 전문가.
*   **일반 사용자:** 자신의 관심사나 프로필을 세련된 페이지로 요약하여 공유하고 싶은 누구나.

---

## 2. 핵심 기능 목록

### 필수 기능 (Must-have / MVP)
1. **사용자 인증:** Firebase 기반 구글 소셜 로그인 (온보딩 간소화)
2. **프로필 관리:** 닉네임 기반 URL 슬러그 자동 생성 및 실명/바이오 인라인 편집
3. **링크 관리:** URL 추가/편집/삭제 및 Google Favicon API 연동을 통한 아이콘 자동 자동화
4. **반응형 프로필 페이지:** 모바일 퍼스트 디자인 기반의 공개 프로필 페이지
5. **실시간 프리뷰:** 대시보드 수정 내용이 즉시 반영되는 시각적 피드백

### 선택 기능 (Nice-to-have / v2.0)
1. **통계 분석:** 링크별 클릭 횟수 및 기간별 방문자 분석
2. **테마 커스터마이징:** 배경색, 버튼 스타일(Round/Sharp), 폰트 선택 기능
3. **SEO 최적화:** 공개 프로필의 메타 태그(제목, 설명, 대표 이미지) 설정
4. **링크 정렬:** 드래그 앤 드롭을 통한 링크 순서 변경

## 3. 기능 상세 설명

### 3.1. 사용자 인증 및 계정 관리
*   **로그인 방식:** **Firebase Auth (Google Social Login)** 전용. 이메일/비밀번호 가입 절차를 제거하여 이탈률을 최소화합니다.
*   **URL 슬러그 정책:** 가입 시 구글 이메일의 ID 부분을 초기 `displayName`(URL 슬러그)으로 할당합니다. (예: `mylink.site/nsy`)
*   **회원 탈퇴:** 사용자 데이터 및 관련 링크 정보의 완전 삭제 기능을 제공합니다.

### 3.2. 관리자 대시보드 (Admin Interface)
*   **인라인 텍스트 편집 (Inline Editing):** 
    *   사용자의 `username`(페이지 노출 이름), `bio`(소개글)를 별도 저장 버튼 없이 텍스트를 클릭하여 즉시 수정할 수 있습니다.
    *   수정 시 Firebase Firestore에 실시간 업데이트(Debounce 적용)를 수행합니다.
*   **링크 리스트 관리:**
    *   **링크 추가:** 제목(Title)과 URL 입력 시 즉시 생성.
    *   **아이콘 자동화:** Google Favicon API(`https://www.google.com/s2/favicons?domain=[url]&sz=64`)를 사용하여 별도 아이콘 업로드 없이도 전문적인 UI를 완성합니다.

### 3.3. 공개 프로필 페이지 (Public Profile)
*   **네오브루탈리즘(Neobrutalism) 스타일:** 
    *   강렬한 하이 콘트라스트 색상, 두꺼운 블랙 보더, 하드 섀도우를 사용하여 현대적이고 힙한 프리미엄 디자인을 적용합니다.
*   **반응형 레이아웃:** 
    *   모바일 환경에서는 꽉 찬 리스트 형태, 데스크탑에서는 중앙 카드 형태의 레이아웃을 제공합니다.
*   **공유 기능:** 상단에 현재 페이지 전체 주소를 클립보드에 복사하는 버튼을 상시 노출합니다.

## 4. 기술 스택 및 데이터 정책

| 구분 | 기술 Stack | 비고 |
| :--- | :--- | :--- |
| **Frontend** | React / Next.js (App Router) | SEO 및 빠른 렌더링 성능 확보 |
| **Styling** | Vanilla CSS / Tailwind CSS | 디자인의 유연성과 빠른 프로토타이핑 |
| **Backend** | Firebase (Firestore, Auth) | 서버리스 아키텍처로 인프라 관리 최소화 |
| **API** | Google Favicon API | 외부 소스 기반 아이콘 자동화 |

### 데이터 모델 구조
*   **Users (Collection)**
    *   `uid`: 고유 키
    *   `displayName`: URL 슬러그 (Unique)
    *   `username`: 프로필 노출 이름
    *   `bio`: 소개글
    *   **Links (Sub-collection)**
        *   `id`: 링크 고유 ID
        *   `title`: 링크 제목
        *   `url`: 목적지 URL
        *   `createdAt`: 생성 시간

## 5. [제안] 추가 개선 사항 및 아이디어

사용자 경험과 심미성을 높이기 위해 다음 사항을 추가로 제안합니다.

1.  **다크 모드/라이트 모드 지원:** 네오브루탈리즘 스타일은 다크 모드에서 특히 시각적 임팩트가 큽니다. 사용자 환경에 맞춘 자동 전환 기능을 권장합니다.
2.  **마이크로 애니메이션:** 링크 클릭 시나 호버 시 버튼이 눌리는 듯한 'Push' 효과를 추가하여 인터랙티브한 느낌을 강화합니다.
3.  **메타 데이터 미리보기:** 링크를 추가할 때 URL만 입력해도 해당 사이트의 제목을 자동으로 가져와 채워주는 기능을 통해 편의성을 높일 수 있습니다.

## 6. 확인이 필요한 사항 (Open Questions)

명확한 개발 진행을 위해 아래 사항에 대한 의견을 부탁드립니다.

1.  **URL 중복 정책:** `displayName`이 URL 슬러그 역할을 할 때, 만약 다른 사용자가 이미 해당 ID를 사용 중이라면 어떻게 처리할까요? (예: `nsy`가 이미 있으면 `nsy1` 등으로 자동 추천 또는 경고)
2.  **프로필 이미지:** 현재는 텍스트 위주지만, 알파벳 첫 글자를 딴 아바타나 기본 아이콘이라도 프로필 상단에 노출할 계획이 있으신가요?
3.  **최종 배포 도메인:** `mylink.site/[slug]` 형태를 생각하고 계신가요, 아니면 다른 도메인 형식을 선호하시나요?
