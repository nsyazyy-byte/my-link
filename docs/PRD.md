# 마이링크 (MyLink) 제품 요구사항 정의서 (PRD)

## 1. 프로젝트 개요
### 1.1. 프로젝트명
마이링크 (MyLink)

### 1.2. 목적
사용자가 흩어져 있는 자신의 여러 소셜 미디어, 포트폴리오, 블로그, 쇼핑몰, 웹사이트 링크 등을 단 하나의 URL로 모아서 공유할 수 있는 '통합 링크 프로필 서비스'를 제공합니다. 직관적이고 커스터마이징 가능한 사용자 경험(UX)을 통해 퍼스널 브랜딩과 마케팅 효율을 높입니다.

### 1.3. 대상 사용자
*   **크리에이터 / 인플루언서:** 다양한 플랫폼(유튜브, 인스타그램, 틱톡 등)에서 활동하며 팬들에게 모든 채널을 한 번에 안내하고 싶은 사용자.
*   **프리랜서 / 비즈니스 오너:** 자신의 포트폴리오, 서비스 소개, 예약 및 구매 링크 등을 하나의 통합 페이지로 제공하고자 하는 사용자.
*   **일반 사용자:** 자신의 관심사나 기록, 자주 가는 링크 등을 하나의 프로필에 담아 지인들과 공유하고 싶은 사람 누구나.

---

## 2. 핵심 기능 목록

### 필수 기능 (Must-have / MVP)
1. **사용자 인증 및 계정 관리** (Firebase 연동 무설정 구글 소셜 로그인 전용)
2. **프로필 관리** (실제 이름(username), 표시할 닉네임(displayName) 및 한 줄 소개(Bio) 인라인 편집 기능)
3. **링크 관리** (URL 추가, 인라인 수정, 삭제 / 아이콘은 구글 파비콘 API 명세 활용)
4. **프로필 페이지 퍼블리싱** (모바일 최적화된 닉네임 기반 고유 공유용 URL 페이지 제공)

*(참고: 추후 링크의 클릭 조회수 통계를 확인하는 기능이 추가될 예정입니다.)*

## 3. 기능 상세 설명

### 3.1. 사용자 인증 및 계정 관리
*   **회원가입/로그인:** 빠르고 간편한 온보딩을 위해 **Firebase 기반의 구글 소셜 로그인**만 단일 방식으로 제공합니다. (별도 이메일/비밀번호 가입은 미지원)
*   **URL 슬러그(Slug) 자동 생성 및 설정:** 가입 시 구글 연동에 사용된 **지메일(Gmail) 주소의 앞부분(@ 앞의 ID 부분)**을 시스템이 자동으로 추출하여 `displayName`의 초기값으로 설정합니다. 이렇게 설정된 `displayName` 값은 곧 프로필 고유 접속 주소인 URL 슬러그(예: `https://domain.com/[displayName]`)로 작동합니다.

### 3.2. 관리자 대시보드 - 프로필 관리
*   **인라인 편집 (Inline Edit):** 새로운 페이지나 팝업으로 이동하지 않고, 사용자는 대시보드 화면상에서 자신의 실제 이름(username), 닉네임(displayName) 및 바이오(짧은 소개글) 텍스트를 직접 클릭해 그 자리에서 즉시 수정할 수 있습니다. (프로필 이미지 업로드는 지원하지 않음)

### 3.3. 관리자 대시보드 - 링크 관리
*   **링크 추가 및 설정:** '새 링크 추가' 버튼을 눌러 표시될 제목(Title)과 목적지 주소(URL)를 입력합니다. 대상 링크의 아이콘은 자체 서버에서 파싱하지 않고 **Google Favicon API (`https://www.google.com/s2/favicons?domain=...`)**를 호출하여 클라이언트 측에 자동 렌더링되게 합니다.
*   **링크 인라인 수정 및 삭제:** 추가된 낱개의 링크들에 대해서도 제목이나 URL 텍스트를 직접 클릭하여 인라인 편집이 가능하며, 해당 링크를 삭제할 수 있습니다.

### 3.4. 공개 프로필 페이지 (Public View)
*   **반응형 웹 UI:** 사용자에게 공유될 실제 페이지입니다. 모바일에 최적화된 세로형 리스트 형태를 기본 골격으로 하되, 태블릿이나 데스크탑 환경에서도 너무 비어보이지 않게 중앙 정렬되거나 콘텐츠가 적절히 확장(카드 컴포넌트 등)되는 유연한 레이아웃을 제공합니다.
*   **클립보드 복사:** 링크트리처럼 프로필 상단이나 하단에 자신의 페이지 주소를 쉽게 복사할 수 있는 '공유하기' 버튼을 배치합니다.

## 4. 기술 스택 및 정책 결정 사항

앞선 논의를 통해 MVP 단계에서 확정된 주요 기술 및 서비스 정책은 다음과 같습니다. 이를 바탕으로 향후 요구사항에 맞춘 사용자 시나리오 및 UI 와이어프레임 설계 작업이 진행됩니다.

1. **인증 및 데이터베이스:** 파이어베이스(Firebase)를 도입하며, 회원가입 절차 최소화를 위해 인증 방식은 **구글 소셜 로그인 단일 방식**으로 구축합니다.
2. **데이터베이스 모델링:** 유저 문서(Document)에는 URL 경로를 지정할 닉네임인 `displayName` 속성과 프로필 화면에 노출될 실제 이름인 `username` 속성이 모두 포함되어야 합니다. 또한, 각 사용자의 개별 링크 데이터 등은 유저 문서 하위에 위치하는 **서브 컬렉션(Sub-collection)** 형태로 분리하여 구조화합니다.
3. **URL 슬러그 및 노출 네이밍 분리 설계:** 고유 식별자이자 URL 슬러그(Slug) 역할은 지메일 계정 기반으로 생성되는 `displayName`이 담당하며(`mylink.site/[displayName]`), 이를 통해 페이지 접속이 이뤄집니다. 반면, 접속한 페이지 상단에 실제 텍스트로 노출되는 이름은 `username` 필드가 담당하는 투트랙 정책을 적용합니다.
